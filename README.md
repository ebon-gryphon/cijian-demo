# 此间 · 双人日记

2026-09-14 整体整改。产品只保留「写日记」与「共同记忆」。

## 使用流程

1. 创建双人日记，把邀请码交给另一人；双方分别填写自己的片段。一人先写即可。
2. 选择忠实记录或自由创作，按需选取旧记忆，AI 生成故事后直接编辑标题、正文。重新生成前保留上一版。
3. 点击配图，先确认风格、画面、人物细节与比例，再由 AI 整理提示词；也可自行填写。确认后调用图片服务，预览满意再放入日记。
4. 上传或粘贴 JPG/PNG/WebP，可直接配图，也可输入要求改图或做静态特效。修改图保留原图，可恢复。
5. 保存进入共同记忆，支持搜索、继续补写、刷新与导出。双方同时修改时会提示合并。

## 运行

需要 Node 22.13+。`npm run dev` 启动，`npm run build` 构建，`npm test` 检查故事生成与数据边界。

云端结构化日记使用 D1，图片使用 R2。数据库结构位于 `db/schema.ts`，迁移文件位于 `drizzle/`；不要删除历史迁移或原表，以免丢失旧数据。开发环境需要应用三个 SQL 迁移后体验创建/加入。身份沿用原双人空间，以 HttpOnly Cookie 保存，每个空间最多两人。

AI 默认走 OpenAI 的 Chat Completions 与 Images API（generations / edits），没有模拟成功或模板替代。页面右上角可填写自己的 API Key，密钥仅在当前页面内存中使用，不写入存储。也可通过服务端环境配置 `DIARY_API_KEY`、`DIARY_TEXT_MODEL`、`DIARY_IMAGE_MODEL`；使用服务端密钥需要连接双人日记。模型 ID 可调整为账户支持的模型。

没有密钥时可以手写、编辑、上传、保存，生成按钮会返回明确提示。离线文件没有 API 后端，因此不支持 AI 调用和跨设备同步。

## 数据与兼容

默认保存到云端。用户可主动选择「仅在本机体验」，在同一浏览器切换双方视角；此模式用 IndexedDB 存储日记和图片。未提交草稿也临时存于 IndexedDB。

旧版 `cijian-two-person-diary-v1` 日记与 `between-us-demo-v1` 中已共享的共同记忆会迁入本机记忆，私人记忆不自动共享。旧存储不删除。旧共同记忆未记录日期时，以迁入日期作为日记日期。云端转存旧日记时，把其原始片段作为导入者提供的素材，不冒充另一人提交。

旧版装扮、小游戏、关系画像、聊天和接待入口与实现已移除；旧数据库表保留作历史数据。整改前源码归档在同级 `此间-整改前备份-20260914/source.tar.gz`。

## 验证与边界

- `npm test`：迁移、私有记忆排除、保存校验、真实模型输出解析、错误脱敏、生图确认、原图编辑请求。
- 双人云端测试：创建/加入、两人上限、跨身份读取、版本冲突、禁止修改对方片段、空间及图片隔离。
- 浏览器测试：故事编辑、本机保存恢复、图片需求澄清、提示词失败保留、上传和改图入口、移动端布局。
- 真实 AI 生成效果需要可用 API Key 与对应模型权限。当前没有凭据，未做付费模型实测。
- 特效首版提供静态图片修改，不包含动态视频特效。
