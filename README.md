# 此间 · 我们的关系空间

这是一个根据「双方对自己和彼此的认识 → 关系知识库 → 忙碌时代理接待」构想制作的中文交互 Demo。以异地情侣林屿与许知夏作为虚构示例。

## 一键下载体验

当前工作区包含 v0.5.0 更新。

**[下载 Demo 体验包（ZIP）](https://github.com/ebon-gryphon/cijian-demo/releases/latest/download/cijian-demo.zip)** · [查看版本与附件](https://github.com/ebon-gryphon/cijian-demo/releases/latest)

1. 点击上方下载链接，保存 `cijian-demo.zip`（无需登录 GitHub）。
2. 解压整个压缩包，打开 `cijian-demo` 文件夹。
3. 双击 **index.html**，用 Chrome、Edge 或 Safari 开始体验。

无需安装 Node.js、运行命令或填写 API Key。推荐在电脑浏览器体验；手机的文件预览器不一定能运行交互页面。不要直接在压缩包内打开文件。

普通体验者选择 `cijian-demo.zip`，无需下载 GitHub 自动生成的 `Source code` 源码包。如果下载未开始，可进入版本页面，在 **Assets** 中选择体验包。

体验包仅包含 `index.html` 和 `README.txt`。也可以在版本页面直接下载 `index.html`，保存到电脑后用浏览器打开；GitHub 文件预览页面不会运行 Demo。

## 已有源码时打开体验

直接双击本文件夹中的 **打开此间.html**。不需要启动服务，不需要 API Key；页面运行时不调用云端模型。请用 Safari、Chrome 或 Edge 打开。如果系统预览只显示代码，右键选择浏览器打开。

数据仅保存在当前浏览器的本机存储中。浏览器不允许保存时仍可体验，但刷新后可能恢复示例。单文件版本和本地开发预览的存储相互独立。切换身份是演示操作，不是真实账号鉴权。

## 小规模联机测试

网页版本新增 `/online` 联机测试入口。第一位测试者填写称呼并创建空间，将 6 位邀请码发给另一位测试者；两台设备进入同一个空间后，消息保存在服务端并每 3 秒同步。测试身份凭证只保存在各自浏览器中，当前不接入手机号、邮箱或微信登录。

任一方可以把自己设为忙碌并开启助手。对方发来消息时，服务端会生成接待回复；未配置服务端模型密钥时使用基础规则，配置后使用统一的模型服务。关系决定和承诺类内容仍标记为需要本人回应。

## v0.5.0 更新

网页版本已接通 OpenAI / DeepSeek 的真实模型请求；未配置密钥或离线打开时使用基础规则回复。助手设置现包含接待设置、模型设置和“口吻记忆”。首次打开会显示三步轻量引导，可跳过，也可从账号菜单重新打开。

## 口吻学习与模型接待

两人的口吻记忆独立保存在本机。用户无需先设置回复长度、语气或风格标签；AI 会根据本人亲自发出的新消息和口吻修正自主学习，用户可在理解不准时直接修改或删除 AI 归纳的口吻记忆。学习不会回读旧消息，也不会把对方或 AI 回复当成本人样本。保留最近 40 条，可查看、逐条删除或全部清除；关闭开关后停止自动学习，也不向模型提供口吻记忆或样本。自动摘要由句长、表情和重复语气词归纳，不推断性格。用户修改过的记忆和口吻修正优先。

切换到助手所属者的演示身份后，点击其 AI 消息下的“这句不像我”，填写自己会说的话；该表达优先用于后续口吻学习，不会改写或重新发送历史消息。清除口吻不会删除聊天，也不会重新扫描旧消息。

真实回复需要在接待者自己的“模型设置”中填写有效 API Key。密钥从旧本机配置迁移至当前标签页 sessionStorage，localStorage 不再保存密钥；刷新标签页可继续使用，结束会话后需重新填写。切换 API 服务会清空输入中的密钥，避免将同一密钥发给另一个服务。此演示没有账号隔离，不能作为线上密钥保管方案。

网页通过 `/api/reception` 向所选服务发送最多 12 条近期对话、30 条已确认共享记忆的文字和接待者口吻参考，不上传附件字节。模型可以回复普通日常话题；承诺、决定、感情表态和缺失的个人事实应交回本人，情绪安慰后仍提醒本人关心。服务端与客户端校验结构、引用和明确越界表达。语义判断仍依赖模型，并不保证识别所有边界；上线前需要真实模型场景评估。请求失败会明确标注基础接待，未答内容继续进入交接。

模型请求限制为 45 秒，客户端等待最多 60 秒。切换身份、本人接回、关闭接待或修改口吻/模型/共同记忆时取消在途回复，避免旧结果追加。正在生成时暂缓同一方向的下一次发送。

自定义接口需支持 Chat Completions、JSON 输出和 `max_tokens`，仅允许 HTTPS。部署者在运行环境中设置 `MODEL_ALLOWED_ORIGINS`，例如 `https://api.example.com`（多个 origin 以逗号分隔），再在界面填写包含版本路径的地址，例如 `https://api.example.com/v1`。服务端精确匹配允许的 origin 并禁止重定向；默认不允许任何自定义主机。不要将不受信任或内部服务列入允许名单。

共同记忆支持添加图片和普通文件，不再支持上传视频。图片可直接预览，文件可打开或下载；每条记忆最多 6 个附件，单个不超过 100 MB。附件字节保存在当前浏览器的本地数据库，不会跨设备同步。

## v0.4.0 更新

“回来接着聊”现为“待你回应”，只收录 AI 未能回答的部分，关系决定、情绪感受优先展示。已答清楚的内容不重复列入，未经 AI 接待的普通留言也不进入这份列表。

助手功能已融入聊天框标题栏，侧栏去掉双人姓名、装饰文案和单独滚动；左下角头像菜单保留登录 / 账号和设置。切换体验身份使用页面右上方的按钮。登录弹窗明确真实账号登录尚未开放。

私人记忆空间、收藏、回忆纪念模式，以及聊天中的欢迎回来提示已移除。新建记忆双方可见，关于对方或共同经历的内容仍需对方确认后才供助手引用。

## 建议体验顺序

1. 在默认许知夏视角发送“你几点忙完？今天有点委屈。晚饭吃什么？”。
2. AI 回答已知忙碌时间，其他片段留给本人。
3. 点击页面右上方“切换为林屿”，进入“待你回应”。已答的忙碌时间不在列表中；情绪片段优先，晚饭问题随后。可以展开原消息和 AI 回复。
4. 点击“回应这些内容”亲自回复，对话同步更新、待办关闭。已经线下回复时，可点“已当面回应”。
5. 在“彼此的模样”回应对方的理解，或到“共同记忆”写一条愿意分享的信息。关于对方和共同经历的记忆，需要另一方确认；不符合或暂缓的内容不参与接待。
6. 在聊天框标题栏的开关或接待设置中控制自己的助手；状态仍支持在线、手动忙碌和离开两分钟后自动接待。

## 演示边界与旧数据

首页和离线文件仍是同机交互原型；`/online` 提供邀请码测试身份、双人数据隔离和跨设备消息同步，但不等同于正式账号系统，也不支持微信代发。配置模型的网页版本结合模型语义判断与规则检查，离线版仍按关键词接待。助手关闭或未进入接待状态时，来信仅留在对话，不会被误计为“AI 未答”。

原路径、原浏览器中的旧聊天和共同记忆可继续读取。旧版私人记忆保留在原存储，但不再展示、参与回复或自动变成共享内容；旧收藏存储不再读取。本次功能移除不会清空旧版本机数据。

引用面板仍显示记忆当前版本，历史对话不会随记忆更新而改写。忙碌状态依据页面可见性与窗口焦点；返回页面暂停自动接待，手动忙碌需主动接回。关闭页面后不能持续接待。请勿将这个版本当成真实消息服务或输入真实秘密。

历史说明见 [v0.5.0](docs/release-v0.5.0.md)、[v0.4.0](docs/release-v0.4.0.md)、[v0.3.0](docs/release-v0.3.0.md) 和 [v0.2.0](docs/release-v0.2.0.md)，以本节当前能力为准。

## 源码开发

Node.js 22.13+（建议 24）。下载或克隆源码后，在本文件夹运行 `npm ci`，再运行 `npm run dev`，打开终端显示的本地地址。

- `app/page.tsx`：界面、记忆管理、身份切换、消息交接。
- `app/online/room.tsx`：双设备测试空间、邀请码加入和消息同步。
- `app/api/beta/`：测试身份、状态和消息接口。
- `db/schema.ts`：D1 数据表定义，`drizzle/` 保存数据库迁移。
- `app/demo.ts`：数据结构、示例数据和接待规则。
- `app/presence.ts`：自动状态、手动覆盖与页面事件监听。
- `app/globals.css`：视觉样式和响应式布局。
- `scripts/build-offline.mjs`：打包单文件离线版本。
- `tests/reception.test.mjs`：接待证据与隐私规则测试。
- `tests/interaction.test.mjs`：理解回应、身份命名、状态边界与事件测试。
- `tests/handoff.test.mjs`：未答片段、优先级、处理完成、旧消息关联和持久化恢复测试。
- `tests/reception-model.test.mjs`：模型请求、边界交接、引用与自定义接口安全测试。
- `tests/speaking-style.test.mjs`：口吻样本、修正、关闭和清除测试。
- `tests/attachments.test.mjs`：附件类型、数量、大小和文件显示测试。

验证与打包：`npx tsc --noEmit`、`node --test tests/*.test.mjs`、`npm run build`、`node scripts/build-offline.mjs`。

页面还在支持 WebMCP 的环境提供读取演示状态、发送演示消息的接口。未进行浏览器端 WebMCP 实测，不影响常规网页操作。

## 制作下载包

修改界面后，先运行 `npm run build` 和 `node scripts/build-offline.mjs` 更新离线页面，再运行 `python3 scripts/package-release.py`（需要 Python 3）。仅重新打包现有离线页面时，可直接运行最后一条命令。

脚本会在 `.releases/` 生成 `cijian-demo.zip`、单独的 `index.html` 和 `SHA256SUMS.txt`。发布 GitHub Release 时上传这三个附件；此目录不会提交进源码。体验包不包含依赖、环境变量、本机缓存或用户的浏览器聊天记录。

## 后续接入真实产品

联机测试已经接入两人测试身份、服务端访问控制、消息持久化和基础接待。下一步把共同记忆、确认记录、口吻修正和待回应事项迁移到按空间隔离的服务端存储，再用真实测试对话评估语义边界和口吻效果。判断产品价值的重点是双方是否愿意使用与是否减少漏接，而非单纯提高聊天时长。

项目继续通过 GitHub 仓库与 Release 分发离线 Demo；Sites 上保留小规模联机测试版，默认仅项目所有者可访问，开放给测试者前需单独调整访问范围。
